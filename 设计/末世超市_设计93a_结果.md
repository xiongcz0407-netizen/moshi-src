## 3. 主开发操作清单
1. **开始做一个设计 dXX 之前**：在自己的云端副本里 `git checkout main && git pull`，再 `git checkout -b dXX`。
2. 改代码、测试、截图，都在自己的云端副本里。
3. `git commit -m "设计XX：一句话说改了什么"`，`git push -u origin dXX`。
4. **合并**（自己的分支，或者副开发的分支）：
   - `git checkout main && git pull`，然后 `git merge --no-ff dXX`。
   - 有冲突时 git 会在文件里标出 `<<<<<<<` 两边；看清楚两边各改了什么，两边都要留的就都留。结果文档里写清楚冲突在哪个文件、怎么解决的。
5. **只有主开发做**：
   - 改 `src/js/version.js`（APP_V +10）；
   - 写 `src/js/changelog.js`；
   - 改 `help.js` 的说明（副开发写在结果文档里的文字，照贴）；
   - 单独提交一次：`版本 V8.xx：合并 dXX、dYY`，`git push`。
6. **打包发布**：`node build.mjs <目录> @INJECT`，把产物（只有 `game.js`、`index.html`、`style.css`、`version.json`、新的图片和模型）放到 `Claude outputs/_syncNNN/gh.tar`。在你电脑上解压到 `morichaoshi`、填令牌、`git add`，由你提交。
7. **更新你电脑上的文件夹**：在「末世超市」文件夹里 `git pull`（只做这个，不在这里改代码）。**不再用 src.tar 整包解压。**
8. 结果文档、截图照旧：结果文档写进项目，并放在 `设计/` 里跟代码一起提交；截图放 `美术/检查截图/`，不进仓库。

## 4. 副开发操作清单
1. 开始前：`git checkout main && git pull`，`git checkout -b dXX`（一个设计一个分支）。
2. 只改这次设计文档「要改的文件」里列的文件。要动别的文件，先在结果里说清楚。
3. **不改**：`version.js`、`changelog.js`、`help.js`。要加的说明、更新记录文字写在结果文档里。
4. `git commit -m "设计XX：……"`，`git push -u origin dXX`。
5. 结果文档最后一行写：「请主开发合并 dXX、加版本号、写更新记录、打包」。
6. 不往「末世超市」文件夹、`morichaoshi` 里写任何东西（截图除外，放 `美术/检查截图/`）。

## 5. 什么任务可以并行
- 设计文档写清楚「这次要改的文件」。两份设计改的文件不重叠，才分给两个 agent 同时做。
- 改同一个文件的（比如两个都改 `fbcore.js`），排队做或者给同一个 agent。
- `version.js`、`changelog.js`、`help.js` 只有主开发改，所以不算重叠。
