# 设计74a：副本读取失败后一直进不去、白扣尸潮卷 —— 结果（V5.81）

版本：V5.71 → **V5.81**（APP_V 581）。存档格式没变。
截图：`美术/检查截图/1022_设计74/`

## 改了什么（照文档 6 条）
1. **读失败不再被记住**（fb.js `load()`）
   - 14 个副本 GLB 每个失败自动重试 2 次，隔 1 秒。
   - 整体失败时把缓存的 Promise 清掉，下次进副本重新读。
   - 贴图（assets.js `lazyTex`）失败隔 1 秒再试一次。
2. **场地建一半出错从头再建**（fb.js `build()`）
   - 出错时把 `scene` / `boss` / `mixer` / 贴图都清掉再抛出，下次进副本从头建。
   - 效果跟「先建在局部变量里，建好才赋值」一样：失败后不会留下半个场地。
   - `enter()` 读、建出错时，把副本状态（active、HUD）也清掉。
3. **进去了才扣尸潮卷**（main.js `fbGo` / `fbAgain`）
   - 顺序改成先 `FBV.enter`，成功后才 `fbStart`（扣卷、run = n、存档）。
   - 读失败：卷本来就没扣，`S.fb.run = 0`，存档。
   - 「再打一次」读失败时也一样，人回到超市。
4. **提示和记录**
   - 提示改成「副本没读出来（网络不好？），尸潮卷没扣，再试一次」，显示 5 秒。
   - 出错的文件名和原因（比如「butcher.glb：Failed to fetch」）记在两个地方：
     - 性能小窗里一行红字（「副本读取失败 N 次：…」）；
     - `?debug` 的 `__g.FB_ERR`（最近 5 条，带时间）；
     - 同时 `console.error('[副本读取]', …)`。
5. **后台先读**
   - 超市到 5 级以后，走到传送门 8 米内（每 30 帧看一次），或者点「进入副本」打开面板时，在后台 `FBV.preload()`。
   - 后台读失败不提示，5 分钟内不再自己读，免得断网时一直下；点「挑战」时照常读。
6. **失败后主角走回门前**
   - 回到超市画面、恢复 HUD，主角从门里走到门前（跟 fbLeave 一样），不卡在门柱中间。
   - 「再打一次」失败时，人先放到门口再走出来。

另外在 fbcore.js 加了一个测试用的 `killBoss()`（跟原来的 `forceCast` 一样只给测试用），用来测「打赢」。

## 测试（无头 Chrome，V5.81，xiongcz2 存档，尸潮卷先设成 10）
「请求」都用 page.route 拦截。脚本：t74.mjs（场景用 SCEN 选）、t74e.mjs（「再打一次」失败）、t74f.mjs（失败提示和性能小窗截图）。

| 场景 | 结果 |
|---|---|
| cart.glb 第 1 次请求失败 | 自动重试就过了，第 1 次就进去了，卷 10 → 8 |
| cart.glb 前 3 次请求都失败（把第 1 次进副本的 3 次尝试都用完） | 第 1 次：提示，**卷还是 10，run 0**，主角走回门前（-11.4, -20）；第 2 次：进去了，卷 10 → 8 |
| 14 个 GLB 一直失败（断网） | 连点 3 次：每次都提示，**卷一直是 10，run 一直是 0**，主角每次都回到门前；性能小窗写「副本读取失败 N 次：butcher.glb：Failed to fetch」 |
| 正常：进 → 打赢 → 回超市 → 再进 → 撤退（算输）→ 再打一次 | 卷 10 → 8 → 6 → 4；打赢、输了 run 都回到 0，「再打一次」后 run = 1，跟以前一样 |
| 输了以后「再打一次」读失败（测试里让 enter 抛错） | 卷不扣（8），run 0，回到超市、HUD 正常，主角站在门前 |

- 改前在复现里，第 2 次进也失败、每次扣 2 张卷。现在第 2 次能进，失败不扣卷。
- 断网时连点几次也不会白扣卷。

**WebKit（接近 iPhone Safari）没跑成**：这里下载 Playwright 的 WebKit 被网络挡了（Download failure），装不上。代码里没有用到只有 Chrome 才支持的东西：只用了 fetch 读 GLB 和 Image 读贴图，加的是 Promise 重试、setTimeout。要在 iPhone 上确认的话，请你：
1. 进一次副本，看能不能进；
2. 进不去时打开设置里的性能小窗，看红字写的是哪个文件、什么原因，告诉我。
