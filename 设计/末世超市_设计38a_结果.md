# 设计38a：国内加载慢（V3.01）

## 1. 主角模型
- people/hero_m2.glb：**10.37 MB → 1.56 MB**。
- 贴图：
  - 两颗发型头原来是 2048 的 PNG，两套衣服是 1024 的 PNG，都改成 1024 的 JPG。这 4 张图都不透明，所以不用留 PNG。
  - 法线贴图本来就是 1024 的 JPG，没改。
- 模型：用 meshopt 压缩（EXT_meshopt_compression），顶点量化，位置用 16 位精度。顶点数一个没少（4 块一共 52,625 个，跟原来一样）。
- 对比截图在 `美术/检查截图/1020_设计38/`：
  - 对比_近景全身：形状、手完全一样。
  - 对比_近景脸：放到整张图只看脸，眼睛、头发的贴图稍微软一点，形状不变。
  - 对比_游戏里主角：游戏里看不出区别。
- 旧主角 hero_m.glb 也压了：0.83 → 0.32 MB。它是第 4 条用的「替补」主角。

## 2. 所有 GLB 一起压
- 规则：
  - 贴图最大 1024。不透明的转 JPG，带透明的留 PNG。256 以下的 Kenney 小色板图不动（转 JPG 会把色块边弄糊）。
  - 模型用 meshopt 压缩。
  - 有 7 个 Kenney 小模型 meshopt 压不了（货架 3 个、船 3 个、水晶塔 1 个），保持原样，一共只有约 0.5 MB。
- 一共 **41.1 MB → 18.6 MB，少了 55%**。models 文件夹（带 PNG 皮肤图）43 → 21 MB。

| 文件夹 | 压缩前 MB | 压缩后 MB |
|---|---|---|
| ws 工坊、货柜、池塘 | 19.29 | 10.88 |
| people 主角 | 11.20 | 1.88 |
| td 塔防 | 1.66 | 0.63 |
| recycler 回收机 | 1.61 | 1.10 |
| pirate 海盗包 | 1.58 | 0.95 |
| 商人、人物、M16 | 1.25 | 0.66 |
| survival | 0.92 | 0.55 |
| city / car / market / animals / npc / food / coaster / furniture / water / blaster | 3.58 | 1.97 |

- 游戏里读模型时用 meshopt 解码，读完把顶点数据换回浮点数。合并静态模型、改几何体的代码照旧能用。
- 压完逐处对比过：超市、工坊、牧场、塔、钓鱼区压缩前后一样。
  - 中间发现一个问题并改掉了：Kenney 人物模型本身不带贴图，压缩工具把它的 UV 当成没用的删掉了，顾客变成纯色。现在保留 UV。
- 压缩脚本：tools/glbpress.mjs。

## 3. 缓存
- 打包时给 img、models 下每个文件算内容的短 hash（8 位），网址写成 `xxx.glb?v=hash`。文件没改过，网址就不变，手机直接用缓存。
- 游戏代码里所有读模型、读贴图的地方（包括 GLB 里引用的贴图）统一加 hash。
- HTML 里的图标、style.css 里的背景图，打包时也换成带 hash 的网址。
- 只有 game.js、style.css 还跟着版本号。hero2.js 读主角时不再带 ?v=版本号。

## 4. 加载顺序
1. **先读人物**：
   - Kenney 人物、皮肤图、旧主角 hero_m，一共不到 1 MB；
   - 然后单独读新主角 hero_m2。
2. **再读第一屏的场景**：街、超市、货柜（1 档）、回收机 1 级、牧场、池塘 1 级等。新主角 12 秒还没读完，也照样开始读场景。
3. **进游戏以后在后台读**，按这个顺序：
   1. 超市里看得到的高等级模型：回收机 2～5 级、货柜 2、3 档、池塘 2、3 级、神秘商人。读到之前先显示简易模型或 1 级的样子。
   2. 钓鱼区才用的模型。没读完时点坐船会提示「钓鱼区的模型还在下载」。
   3. 工坊机器、塔。
   4. 商人模型：读到之前先用顾客模型顶着。
   5. 物品图标（135 张约 7 MB），打开面板时没读到的会自己读。
   6. 尸潮特效图。
- 45 秒还没读完新主角时，主角先用旧的 hero_m，读完自动换成新主角，不再出现方块人。实测：让新主角 75 秒才到，进游戏时是旧主角，到了就换上（截图：先用旧主角、换上新主角）。
- 顺手修了一个老问题：网慢、45 秒先进游戏时，以前后台的工坊机器、塔就不再读了。现在会等前面的读完接着读。

## 5. 好友聊天（Supabase）
- 进游戏 10 秒以后才第一次连。
- 连续失败 3 次就停 5 分钟再试。
- 好友面板：
  - 连不上时直接写「好友服务器连不上，X 分钟后自动再试」，还有「国内网络有时连不上好友服务器，不影响玩游戏和云存档」，加一个「再试一次」按钮。不再一直显示「正在连接」。
  - 进游戏不到 10 秒打开时写「进游戏 10 秒后连接好友服务器」。

## 6. 测试
- 性能小窗加了一行，例如：「加载 13.7 秒　下了 9.3 MB（271 个文件，17 个用缓存）」。如果用了旧主角，后面会写「先用旧主角」。后台全部读完以后再加一行「后台又下了 X MB，全部读完 Y 秒」。
- **浏览器限速测试**（200 KB/s，延迟 150 毫秒，服务器按 GitHub Pages 的方式：缓存 10 分钟、js/css 压缩传输）：

| | 进游戏 | 新主角读好 | 下载 |
|---|---|---|---|
| 第一次 | 52.8 秒 | 28.9 秒 | 8.2 MB |
| 第二次（有缓存） | 14.2 秒 | 4.0 秒 | 0 MB |

- 上面的秒数是在云端测试机上量的。这台机器没有显卡，用软件画 3D，光准备场景就要 13～14 秒（不限速、全用缓存也是这么久）。所以：
  - 第一次里网络下载大约占 40 秒，新主角在下载开始约 25 秒时就读好了。
  - 手机有显卡，准备场景只要几秒。估计国内第一次进游戏约 40～45 秒，主角一直是正常的人；第二次几秒就能进。
- 压缩前第一屏要读约 35 MB（光主角就有 10.4 MB）。按 200 KB/s 算要 3 分钟左右，所以每次都卡到 45 秒的上限，用方块人进游戏。
- 进游戏以后后台一共还要读约 18 MB：工坊机器、图标等。网速 200 KB/s 时要一两分钟。
- 其他测试：
  - lint 0 错误；core2、tdg 通过；截图时没有报错。
  - 物品图标、按钮图标在面板里都正常显示（hash 网址）。
