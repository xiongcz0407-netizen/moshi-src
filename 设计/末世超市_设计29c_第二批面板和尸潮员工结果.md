# 设计29c：29b 做完的结果（V2.21）

## 一、29a 的 4 个小问题
1. **紧缺标签**：以前「紧缺」用的是市场的「紧缺事件」（L.isShort，随时间换一种货），跟库存没关系，所以 19/60 的罐头有、0/60 的纯净水反而没有，两次截图又不一样。现在：**仓库 0 个 = 紧缺**（一定显示）；市场紧缺事件改叫 **「涨价」**（橙色，详情里写「涨价 ×1.5」）。
2. **钓鱼用品页签**：要先买**垂钓证**才显示（S.fishLic）。29a 测试用的存档没有垂钓证，所以没出来。这次测试存档加了垂钓证，四个页签都有，见截图「仓库_钓鱼用品」。
3. **667 角色左下折行**：改成固定两行「等级上限 5 级」/「超市 1 级」。
4. **仓库翻页**：固定 5 × 2 一页。用 19 种货测过，2 页，左右翻页，不往下拉（截图「仓库_翻页」）。

## 二、第二批面板（都换成设计 29 的框架）
共同：标题栏资源条 + 「?」+ 关闭；格子一样大，多了左右翻页；点格子右边详情；长说明进「?」。
**换货、升级不整页重画**：框架面板重画时只换变了的部分（那一格、右边详情、分页条），别的格子 DOM 不动（ui.js 的 morphPF）。

- **货架**：页签 = 货柜种类（货架 / 果蔬架 / 冰柜 / 熟食柜，有几种显示几种，有没选货的货柜亮红点）。页签那一行右边是「布置货柜位置」按钮和「货柜 5/12 个」。一格一个货柜：编号 + 名字、摆的货图标（没选的是虚线「空」）、库存条和 n/容量、「没选货」/「升档中」标签。详情：在卖什么、货物图标网格（选中的高亮；仓库 0 个的变灰写「没货」，下面写「灰色 = 仓库没货」）、果蔬架上面一排小按钮切换第几种；最下面升档：多出来的容量（果蔬架还写多几种）、花费图标 + 「升档」按钮，升不了写原因。资源条：末日币、工具箱。
- **员工**：页签 全部 / 收银 / 种地 / 拾荒 / 钓鱼 / 饲养 / 工匠 / 休息（有人的写人数）。下面一条：宿舍楼几级、住了几人、有没有人饿着；有新员工等决定时有按钮。一格一人：品质框头像（带等级、品质）、名字、在干什么。详情分三个小页签：**属性**（现在在干嘛、血量 / 攻击 / 防御 / 效率 → 下一级、升级按钮带花费、请走）、**岗位**（7 个岗位按钮，不能选的写原因，下面一句说明）、**武器**（装 M16 / 卸下、伤害 / 射速 / 射程各一行，升级按钮上是花费图标）。不再单独打开员工详情页（新员工到了点「给他安排工作」也是打开员工面板并选中他）。
- **建造**：页签 建筑 / 牧场 / 工坊 / 塔。下面一条施工队：几队在忙，每队在建什么、进度条、还要多久、发条加速按钮，空闲的写「空闲」，「多雇」去商城。格子：图标、名字、现在几级 → 下一级、花费图标（能建的右上「能建」）；没解锁的图标变灰，写「🔒 需要超市 4 级」这类条件；在建的写「建造中…」。详情：等级、建好以后有什么用、超市还有任务进度、花费图标（含用时）、开始建造按钮。塔：一个塔位一格，空塔位详情里选塔建，有塔的能升级、卖掉。
- **商城**：页签 补给 / 设施 / 员工武器 / 动物 / 星星兑换（钓鱼区商人没有动物和星星兑换）。补给：每日免费发条、肥料 1/5/20、尸潮卷 1/5、有垂钓证以后饵料和鱼竿；设施：施工队、垂钓证；员工武器：M16；动物：6 种，没盖棚的上锁；星星兑换 4 样。格子：图标 + 数量、名字、价格（省多少的贴绿标签）。详情：说明 + 购买按钮。**星星兑换页资源条换成星星 + 末日币**，其他页是末日币 / 发条 / 肥料 / 尸潮卷。

## 三、尸潮员工机会
- config.js：`STAFF.td.repeat = { 3: [0.10, 0.02], 4: [0.12, 0.025], 5: [0.14, 0.03], 6: [0.16, 0.04], 7: [0.18, 0.05], 8: [0.20, 0.06], 9: [0.22, 0.07], 10: [0.25, 0.08] }`（史诗、传说），以后改数字就行。
- logic.js：tdStaffRoll 先判传说、没中再判史诗，最多 1 个；1～2 关、英雄本（lv > 100）返回不出；第一次打赢保底（3 关史诗、5 关传说）不变，只有打赢才判。
- 关卡上：没打赢过的保底关写「第一次打赢必得史诗/传说」，其他普通关写「员工：史诗 x%　传说 y%」，英雄本不写。
- help.js 改成「之后打赢普通第 3 关以上也有机会得到，关卡越高机会越大……英雄本不出员工。」

**GM 验证**（游戏里 `__g.tdSim(关, 1000)`，用的就是结算里的同一个函数，只算不发员工）：

| 关卡 | 表里 史诗 / 传说 | 1000 次里 史诗 | 1000 次里 传说 | 应该是 |
|---|---|---|---|---|
| 2 | 不出 | 0 | 0 | 0 / 0 |
| 3 | 10% / 2% | 113 | 23 | 100 / 20 |
| 6 | 16% / 4% | 162 | 38 | 160 / 40 |
| 10 | 25% / 8% | 250 | 74 | 250 / 80 |
| 英雄 103 | 不出 | 0 | 0 | 0 / 0 |

都在正常的随机波动里（1000 次的误差大约 ±10～14）。另外用 node 直接跑同一函数各 1000 次：3 关 99/16、6 关 151/33、10 关 256/89，也对得上。
