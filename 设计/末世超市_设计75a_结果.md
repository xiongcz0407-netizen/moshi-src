# 设计75a：资源存在手机里，以后只下载改过的 —— 结果（V5.91）

版本：V5.81 → **V5.91**（APP_V 591）。存档格式没变。
截图：`美术/检查截图/1022_设计75/`

## 怎么做的
- **清单**：build.mjs 原来就算每个文件的 hash（HASH），这次再记大小（SIZE），一起打进 game.js。
- **手机资源库**（新文件 assetdb.js）
  - IndexedDB `ms_assets`，表 `files`，每个文件一条 `{ path, hash, blob }`。老 Safari 存不了 Blob 时，改存 ArrayBuffer。
  - 打开时把 hash 对得上的文件都变成 blob 网址。hash 不一样的、清单里没有的，删掉。
- **先检查再开游戏**（新文件 boot.js、assetboot.js）
  - 入口改成 boot.js：先检查资源，缺的、改过的下好，再执行 main.js。
  - three.js 和游戏本体都在 main.js 里。esbuild 打包时把它做成「用到才执行」，所以还是一个 game.js。
  - 这样 main.js 一开始建场景时读的地面贴图等等，就已经能从库里拿了。
  - 最早只在 main.js 里检查：建场景在检查之前就跑了，第二次打开还会从网上下 14 张地面贴图，所以改成这样。
- **下载**
  - 同时 4 个，失败隔 1 秒重试 3 次，下一个存一个。中途关掉，下次只下剩下的。
  - 一个都没下好、已经连着失败 8 个：当成断网，不再一个个试，马上出「重试 / 先进游戏」。不然断网时要等好几分钟。
- **进度条的字**
  - 第一次（或基础包还差三成以上）：「第一次打开，下载资源 12.3 / 26.7 MB」。
  - 以后：「更新资源 3 / 6 个文件（…）」，下完写「更新了 N 个文件（x MB / KB）」，停 0.9 秒。
  - 没有要更新的：不写，直接进加载。
  - 断网：「网络不好，还有 N 个文件没下好」，下面两个按钮「重试」「先进游戏」。先进游戏就照原来的办法，边玩边从网上读。
- **读资源先从库里拿**
  - `A()` 先查库，有就返回 blob 网址，没有照旧 `路径?v=hash` 走网络。three.js 的 DefaultLoadingManager 本来就走 `A()`，GLB、贴图都覆盖到了。
  - 页面里写死的图片：index.html 的 `<img>`、行内样式、style.css 的 `url()`，在检查完以后整条规则换成 blob。
  - ui.js 的物品图标表、星星图标、晶石图标原来在一开始就把网址算好了，改成用的时候才算。
- **Kenney 外部贴图**：three 的 GLTFLoader 是按传进去的原路径（`models/city/x.glb`）算贴图目录的，不是按 blob 网址。所以 `Textures/colormap.png` 还是解析成 `models/city/Textures/colormap.png`，再被换成库里的 blob，不用另外改。测过：第二次打开，场景里 39 张带图片的贴图全是 blob、全读好了，0 张走网络。
- **game.js、style.css**：照旧跟着版本号从网上下，不进库。
- **设置 → 游戏**：加了一行「手机里的资源：存了 26.8 MB… [清掉重新下载]」。点了会确认、先存档，再删库、刷新网页，重新下载。
- **不支持或存不进去**
  - 没有 IndexedDB、打不开（8 秒超时）、读不出来：照旧走网络。
  - 存的时候空间不够：这次下的照样用，只是不存。
  - 性能小窗会写「手机资源库 x MB，这次下了 N 个」，或者「没开：原因」。
- **设计74**：重试、失败不扣卷、失败回门前都留着。设计74 的「后台先读副本」改成先把副本包下进库，再读。

## 测试（无头 Chrome，同一个用户目录 = 同一台手机；资源请求用 page.route 计数 / 拦截）
| 测试 | 结果 |
|---|---|
| 第一次打开 | 进度条从「下载资源 0.4 / 26.7 MB」走到下完，基础包 509 个文件。本机服务器、每个文件故意慢 40 毫秒，约 20 秒进加载。后台包随后下完，库里共 33.4 MB（没下 _hi） |
| 第二次打开 | **模型、图片请求只剩 2 个**：index.html 里的星星图标、style.css 里的登录背景。这两个是浏览器解析网页时就去要的，在资源检查之前，手机上一般走 HTTP 缓存，检查完会换成库里的。进副本、打尸潮：0 个请求 |
| 改一个模型（city/building-a.glb 末尾加 4 个字节）重新打包 | 只下了这 1 个文件（25 KB），提示「更新了 1 个文件（25 KB）」 |
| 下到 40% 关掉 | 关掉时请求了 320 个，再打开只下剩下的 193 个（15.4 MB），合起来正好 509 个 |
| 断网 + 库里有 | 照常进游戏，进副本（卷 10 → 8），打尸潮，都没问题。全程只有登录背景图那 1～2 个请求失败（库里有，界面照常显示） |
| 断网 + 库里没有 | 9 秒后出「网络不好，还有 509 个文件没下好」和两个按钮。点「先进游戏」照原来的办法进了游戏（断网所以没有模型，是原来就有的简易模型） |
| Kenney 外部贴图 | 场景贴图：blob 39 张，网络 0 张，读坏 0 张 |
| 清掉重新下载 | 确认后删库、刷新，从「第一次打开，下载资源」重新下，基础包下好 26.7 MB |
| 设计74 的副本测试（新用户目录） | 进 → 打赢 → 再进 → 输 → 再打一次：卷 10 → 8 → 6 → 4，跟以前一样 |

- **大模型原版那一包**：代码写了「关掉大模型减面才下」，这次没在浏览器里测。
- **WebKit**：没跑成。这里下载 Playwright 的 WebKit 被网络挡住（设计74 也是）。用到的 IndexedDB 存 Blob、`URL.createObjectURL`、fetch 都是 Safari 支持的；老 Safari 存不了 Blob 的情况，已经写了改存 ArrayBuffer 的退路。请你在 iPhone 上看三件事：
  1. 第一次打开的进度条；
  2. 关掉再开，是不是一闪就进了；
  3. 设置里「手机里的资源」显示多少 MB（显示「这台手机存不了」就是退回到了老办法）。
